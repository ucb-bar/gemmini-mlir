# General fresh10 Gemmini compiler

The authored backend in this directory uses the selected editable Merlin compiler, original host lowering/runtime, and one explicit Gemmini terminal encoder. Source axes, numerical boundaries, provenance, storage effects and completion edges survive until their consuming transformations run. Selection uses source geometry and hardware resources; ordinary compilation does not inspect capsule names, timing feedback or expected outputs. Hardware-loop descriptors are not used.

## Implementation and selected routes

`frontend.py`, `linalg_lowering.py`, `model_regions.py` and the source analysis modules build source-derived command and connected-region plans. Original Merlin tensor preparation, CPU arithmetic, bufferization and runtime transport handle typed floating/nonlinear host regions. Required accelerator arithmetic stays on the device. `backend.py` connects these plans to dense, convolution, scalar/per-column readout, residual, pooling and movement implementations; `isa.py` encodes the incumbent and alternatives.

Dense lowering consumes real indexed schedule IR, capacity-derived storage, panel transforms and selected RTL completion laws. Convolution uses NHWC window row runs, input retention and checked compute epochs. A proven 1x1 view feeds the dense emitter without a packing conversion. Numerical lowering keeps i8 products/i32 accumulation, bias seeding, exact f32 scale words, RNE, activation and saturation order. Identity residual readout uses a consumed doubled integer representation and half-scale readout, exhaustively checked over signed-byte input pairs. Source-required resident handles retain their packing, lifetime, reuse and eviction proofs independently of optional performance settings.

The selected small conv-pool policy consumes DMA preparation phases into disjoint private ACC rows, then the shared dense contraction and the original quantized-once-before-maximum chain. Its source/resource class requires one complete bounded image panel, one output-channel tile, the observed 7x7 stride2 window and 3x3 stride2 pool families, and actual storage/effect admission. Both selected products are byte-identical to the measured epoch040 programs. Larger or other families retain the incumbent. Two measured geometries support this class; neighboring timing remains unmeasured, so no validated universal crossover is claimed.

The selected small residual policy uses checked 64-column signed-byte DMA only when the complete tensor fits one private panel and needs fewer rectangles. Exact residual arithmetic, block-major storage mapping and completion fences are preserved; the existing specialized identity route has precedence. Movement, larger tensors and unsupported contracts retain the incumbent. Two original whole-call RTL pairs support the selection; wider movement/residual experiments remain opt-in.

Target-generated RHS transpose scratch uses distinct per-invocation 319-byte entry backings with byte alignment and consumed interior 64-byte aligned pointers. No source tensor alignment changes. This fixes dynamic stack realignment: the complete attention kernel has a 928-byte static RV64 frame. The optional stock host small-buffer promotion gives a 2,672-byte static frame, reduces malloc/free pairs from25 to21, and passed all three complete connected numerical checks. It remains off because complete host-heavy timing is UNKNOWN. Its actual target object, ABI/source-plan checks and promotion records are in `../artifacts/experiments/host_storage036/`.

Optional source preparation reuses actual immutable RHS layout cones. `prepack_weights` removes52 preparation operations on attention while preserving original ordinals, ABI and output writers; native preparation pairs match bitwise and the complete program passed numerics. Timing is UNKNOWN, so it remains off. Offline weight bundles refuse absent payload/caller contracts.
