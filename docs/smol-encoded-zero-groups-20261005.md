# Encoded zero omission: rejected performance screen

The hypothesis was that fresh summaries of the actual stored signed-i8 digits
could omit exact integer product panels and their positive-zero host updates.
Merlin owns the encoded-byte summaries and numeric reconstruction proof; OOT
owns device resources, conditional primitive commands and complete output writes.
No strategy uses a model identifier, previous input or golden output.

## Exactness and source scope

Independent strict Spike and actual GSIM tests cover all-zero and nonzero data,
both tails, first surviving products, signed -128 values, dirty destinations and
192 poisoned guard words. All 48 calls match the independent complete integer
reference. Native complete original-head variants match all 65,536 source words
and the unchanged elementwise gate. Their original native replay counts remain
58,369 QK and 4,971 PV; readbacks remain 47,185,920 bytes and 30 group calls.
The separately qualified original target replay count is 58,353 QK. Native counts
must not replace that target count.

Actual low digit Q/K data has zero 16-row panels, but no zero complete 64-row or
256-row panels. A block-only omission at the original blocking therefore misses
the opportunity. The tile-level analytical QK compute census falls from 147,456
to 112,608 commands per signed or absolute phase, with 12,288 extra accumulator
zero DMA commands. Wide B DMA and full output stores/readbacks remain unchanged.
Both original PV parts have no zero encoded 16-row panels on any digit. These are
command counts, not measured occupancy or cycles.

The original large context and smaller completed context remain distinct.
Committed provider IR and machine objects were reproduced byte for byte against
the historical timed objects. Existing historical receipts remain immutable.
No complete original-head target candidate was compiled, no hardware job was
submitted, and no automatic routing was enabled for this losing composition.
