# Smol source to accelerator coverage

Scope: historical whole1906 versus qualified original complete-group2003. These are distinct implementations. No cycle percentage is inferred from retired instructions.

Whole1906 contains297 existing integer catalog calls and384 source BF16 contractions executed as ordered CPU FMA. The new source-bound route covers all384 contractions across48 groups using signed-i8 device products, followed by host reconstruction and source-observation certificates. The complete group uses480 primitive callbacks (12 heads ×8 contractions ×5 degrees); whole native validation observes23,040 callbacks. A callback includes host command issue and synchronization.

| Remaining host stage | Existing device operation / opportunity | Actual blocker or missing proof |
|---|---|---|
| BF16 radix packing and representation witness | Integer input scaling and i8 GEMM exist; prepare immutable operands once across source-proven shared views | DMA scaling consumes integer input, not arbitrary BF16 bit patterns. Bit decomposition, exact power-of-two steps and source equality require a new typed representation producer; equal pointers are insufficient for cross-call reuse. |
| Weighted i32 degree reconstruction | Accumulator accumulation can combine i32 products | Canonical radix weighting requires i64 prefixes; blindly shifting/adding in i32 overflows. Existing grouped-degree device schedule already reduces9 cross-term outputs to5. Narrower device representation needs a proved range, not sampled magnitude. |
| Absolute-product / norm bounds | Existing i8 GEMM can compute exact absolute products or conservative upper products | Implemented and numerically qualified: exact extra9-term route increases total instructions7.79%; single coarse upper plane increases1.735%. Device coverage increases but packing/readback/reconstruction outweigh saved host work under instruction scope; hardware timing remains unknown. |
| Score maximum and source softmax polynomial | Integer max pooling is available; optional normalization RTL exists in source | Stock source configuration sets has_normalizations=false. Integer max pooling does not directly implement source f32 max, floor/bit polynomial, masks, or source-rounded denominator. Requires an order-preserving integer encoding and exact endpoint/nonlinear consumer proof; no such lowering currently qualified. |
| Ordered source denominator and alpha | GEMM against ones can implement integer reductions | Source has eight independent f32 lanes, fixed tree reduction, masks, two-chunk rescaling and original rounding after each operation. Integer real-sum substitution changes semantics; center-only and each one-stage approximation fail original whole gate. |
| Source FMA replay | Signed-i8 plane products already supply real centers | Original ordered f32 rounding cannot be reproduced by the int32 accumulator directly. Ambiguous outputs retain CPU source-order replay. BF16 endpoint equality is not required universally: current consumer certificate permits harmless carrier changes while proving original quantized observations. |
| Final normalization/quantized observations | Accumulator scale, saturation and ReLU epilogues exist | Current values are host f32/BF16, with row-derived escaping BF16 scales and exact source rounding. Reuse of integer epilogue needs a source-bound interval/transition proof and physical producer ownership, as in ResNet readout; currently no accepted Smol route. |

The next useful device mechanism must remove a substantial complete host stage, including its representation/readback overhead. Merely adding an accelerator call is not sufficient.
