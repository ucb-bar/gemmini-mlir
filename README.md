`el4-phase1-capsule-20261019-fresh-v1`, started **2026-10-19 19:14:00 UTC**.
The unchanged final compiler subsequently passed **153/153 public capsules and
8/8 hidden capsules**, including exact numeric comparison and the required trace
and structural evidence. **Formal capsule certification is incomplete:** the

compiler branch. The compiler was authored from an empty submission, without a
handwritten implementation, a seed compiler or a resumed authoring session.
Validated captures, quantized references and hardware facts were reused.

## Workloads and numerical contract

[workloads.yaml](reproduce/workloads.yaml) defines the full selected workloads;
[numerics.yaml](reproduce/numerics.yaml) defines comparisons and reporting.
These definitions describe the intended external evaluation. They are not
evidence that this compiler has completed those evaluations.
The copied numerical policy is a reporting/quality example, not the sealed
models execution configuration. In particular, it retains default cached-twin
settings. The actual selected configuration hash is pinned in the input manifest;
the selected `native`, `portable_exp_trig` and `portable_neural_f32` host policies
are recorded in the workload definition. Do not substitute the example for that
sealed configuration.

| Model | Selected input and complete chain |
|---|---|
| ResNet50 | Pretrained IMAGENET1K_V2; batch 1; NCHW `1×3×224×224`; 1,000 logits |
| TinyLlama-1.1B-Chat-v1.0 | All **22 layers**; batch 1; 32-token prefill followed by 32 teacher-forced decode steps, carrying KV cache and positions |
| SmolVLA base | Full selected policy; batch 1; one `512×512` camera; prefix encode, **10 denoise steps**, action decode; horizon 50; six semantic action channels and 32 stored channels |

There are 46 selected chain steps and 133 declared output arrays across the three
models, including carried state and padding. TinyLlama uses teacher forcing, not
free generation. SmolVLA's selected action decode retains padded channels and does
not apply a physical-unit postprocessor. Capture inputs and external evaluation
inputs have separate provenance; the input manifest records their bindings.

Quantization uses signed static **W8A8**, zero points zero, weights scaled per 16
channels, per-tensor activation scales and INT32 accumulation. The exact
[three recipe JSONs](reproduce/recipes/) and captured scale bytes are the
authority. Attention uses static-head scales and the selected two-plane softmax
recipe. Raw INT32 readout and narrowing INT8 readout have different scale rules;
floating host work remains explicitly declared. There is no implicit
recalibration. Accelerator placement requires every eligible selected operation
to execute on Gemmini, with declared reasons and dispatch evidence for host work.

Functional comparison uses the sealed selected **quantized reference**, exact
shape/dtype/arity, exact integer/boolean outputs, finite floating outputs and
`atol=2e-6`, `rtol=1e-5`. Independent exact accelerator-kernel checks are required.
FP-model quality is reported separately: ResNet cosine/top-k, TinyLlama KL/token
agreement/perplexity, and SmolVLA per-channel normalized RMS metrics. Quality bars,
section-level reporting and unavailable-data rules are in the numerical policy.
No FP-model quality number or end-to-end latency is asserted for this compiler.

## Hardware and timing evidence

Both simulators are selected for the same FireSim Gemmini Rocket configuration,
with verified facts-v6 correspondence: a 16×16 mesh, 64 KiB accumulator and 30 MHz
target clock. **Spike is untuned.** The facts, target contract, Spike,
`libgemmini`, gSIM emulator and timing profile hashes are pinned in the launch
configs. The experiment assigned logical CPUs 6–23, with 16 compute CPUs and two
author CPUs; this is an allocation, not evidence of sustained full utilization.
Owned CPU reservations were released when the qualification exited.

[The gSIM summary](results/gsim-training-evidence-summary.json) and
[training rows](results/gsim-training-evidence.jsonl) retain **159 fresh public
training observations** from the original authoring run, with source, simulator,
shape, instruction-feature, kernel-object and ELF identities. All 159 have paired
Spike executions of the same kernel object; the linked ELF wrappers differ.
Repeated certification-cache hits are not new timing observations. Two stale
program/measurement pairs were excluded. One eligible row lacks complete
component timing fields, so the corpus-wide `timing_ready` flag remains false.

Measured cycle labels cover kernel entry through selected completion, excluding
output publication. Static command/trace features are not a dynamic waveform.
These measurements support later Spike calibration; they are not fitted-model
accuracy, roofline efficiency or full-model latency results. Hidden observations
are excluded from public calibration.

## Reproduction and contents

Run `python3 reproduce/verify_archive.py` to check the public file checksums,
compiler inventory, syntax and observed token totals. It does not compile models,
run simulators or issue a qualification certificate.

The cleaned supporting harness is published on Merlin
[`feat/el4-experiment`](https://github.com/ucb-bar/merlin/tree/feat/el4-experiment).
[software.json](experiment/software.json) pins its reviewed revision and records
the original execution revisions separately. The original runtime was `cd99c863…`;
its config's source baseline was the older `22e91311…`. The qualification runtime
was `0e6260da…`. Cleaned publication history is not a byte-identical rewrite of
those historical execution identities. A new reproduction must bind the selected
published source and regenerate its operator pins and readiness receipts.

1. Provision the harness checkout, Python dependencies, model2MLIR, LLVM/MLIR,
   RISC-V toolchain, bubblewrap and the selected simulator runtimes. Observed
   package versions are listed in `experiment/software.json`; the list is not a
   hermetic dependency lock. Set `MERLIN_MLIR_INSTALL` to the selected LLVM/MLIR
   installation before invoking the compiler.
2. Provision the hash-bound corpus, facts/correspondence proof, instruction
   selection, captures, checkpoints and reference bundle described in
   [input-manifest.json](reproduce/input-manifest.json). These separately owned
   assets are not redistributed here. `NUMERICS_BUNDLE` supplies the numerical
   policy's `MANIFEST.json` and `inputs/`; `examples/` paths name the external
   Merlin checkout. `${MERLIN_REPO}` links in the workload definition are external
   source locations.
3. Copy the [original launch selection](reproduce/original-launch.yaml) and its
   adjacent `errata/` directory into a new preparation area. Bind the paths,
   choose a new run ID, select the actual source revision, and generate valid
   current seals, runtime/operator hashes, all-output plans and readiness receipts.
   The included digests identify historical inputs; path rendering does not
   transfer old receipts to a different source or filesystem.
4. Use the launcher's default check-only mode, then add `--run` after readiness
   passes. This creates a fresh empty submission. Grading the archived compiler
   is a separate post-freeze qualification, using `qualify_phase1.py` and a new
   source-bound invocation; it is not a fresh authoring experiment.

For example, after binding a current configuration and all required assets:

```bash
python "$MERLIN_REPO/examples/gemmini/phase1/launch/launch_phase1.py" \
  --config "$BOUND_CONFIG" --task-root "$TASK_ROOT" \
  --prep "$TASK_ROOT/.tmp/phase1-reproduction" --run-id "$NEW_RUN_ID"
# Repeat with --run only after the readiness result is ready.
```

The [qualification launch selection](reproduce/qualification-launch.yaml) records
the later evaluation settings. The two `*-identity.json` files record the
original configuration hashes and public-rendering hashes. Neither launch YAML
is a ready-to-run replacement for separately provisioned protected inputs.
Reproducibility here means retained compiler bytes, selections, identities and
measurements; exact future agent trajectories and a self-contained redistribution
of hidden assets are not claimed.

Published result projections include:

Raw prompts, authentication, private paths, authoring diaries, hidden test

Published JSONL/CSV files are explicitly sanitized projections, not original
