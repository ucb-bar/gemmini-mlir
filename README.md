# gemmini-mlir — champion branch: `hand_v0`

This branch is a **champion experiment** of the **gemmini** target (family `tensor_resident`),
forked from `main` so it inherits the target base (the Merlin capability contract + the reference
`backend/`) and adds this champion's buildable codegen payload.

Merlin fetches it with `merlin-target-fetch gemmini --champion baseline`, which clones this branch
into `out/build/generated/gemmini/`; the target registry then resolves the target (contract +
`plugin.backend`) and this codegen payload together.

## This champion

- Champion package: `hand_v0` (tag `v0-hand_v0`)
- Family: `tensor_resident`
- Recorded status: `rtl_certified`
- Generated by Merlin's `merlin-target-publish` bridge.

## Codegen payload (this branch)

The buildable C++ dialect tool lives under `payload/` and builds to `build/bin/gemmini-opt`:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./build/bin/gemmini-opt --version
```

The package manifest + provenance ride along under `.merlin/`
(`.merlin/provenance.yaml`, `.merlin/certification.yaml`); each commit here is one promotion.

## Target base (inherited from `main`)

- `contracts/target_contract.yaml` — Merlin capability manifest + `plugin.backend: backend`.
- `backend/` — the reference backend package (evicted from Merlin core's `runtime/backends/`).
- `AGENT.md`, `evidence_concepts.yaml` — target metadata.

See `AGENT.md` for the target brief and the oracle ladder, and `main` for the `<target>-mlir`
convention and how Merlin hooks up to these out-of-tree repos.
