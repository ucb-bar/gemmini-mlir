## What this is

This is a Gemmini compiler. `gemmini-opt` is an out-of-tree MLIR backend written in Python on xDSL (package id
`gemmini_xdsl_oot_backend`). It lowers Merlin's interface dialect to Gemmini RoCC command streams and an LLVM
artifact.

- **Package:** `801eec3ffeb4a25ac7b3d73fee824f2ea1c1efdbab7dd093ab206dfa1891bbca`, 109 files. The digest is Merlin's `hash_tree`.
- **What the branch holds:** the exact bytes that were measured, unmodified, plus Merlin's publication records.
  `sha256sum -c .merlin/records/SHA256SUMS` checks them.
- **Why it is the champion:** it is the fastest package from the phase-2 ResNet-50 campaign under the no-FSM rule.
  No Gemmini hardware-loop (loop-descriptor) instruction appears anywhere in the program.

## How it was produced

1. **Starting point:** the phase-1 compiler cand_07, `1ba5615f` (branch `champions/phase1/1ba5615f`).
2. **cand_07 → `079a9cb8`:** Claude Code with claude-opus-5, over about 40 phase-2 runs. The launcher passed high
   effort; the earliest runs did not record it. The early runs were allowed to use the hardware loop instructions
   (FSM). The later runs open-coded them (no-FSM).
3. **`079a9cb8` → `efaed4dc`:** Codex CLI with gpt-6-sol at high effort, in per-cell runs on the network's stem.
4. **Three cell winners:** separate Codex gpt-6-sol cell runs, each seeded from `efaed4dc`, produced
   `27901e2e` (g1 stem), `4184392d` (3×3 conv) and `036e1d96` (1×1 matmul).
5. **`801eec3f`:** a three-way `git merge-file` of the three winners onto `efaed4dc`.
   - A file changed by one winner was copied from that winner; a file changed by two winners was merged.
   - There were 0 conflicts and no hand edits.
   - An operator-side Claude Code subagent (claude-opus-5-5) did the merge on the coordinator's instruction.
   - Re-running the merge reproduces the files byte for byte (`.merlin/records/COMPOSITION.md`).
   - No agent session authored `801eec3f` as a whole.
6. **Reconstructed history:** this lineage never had a harness git history. Merlin rebuilt one from the stored
   package bytes, checking every hop's digest, and recorded it as `reconstructed: true`:
   `806a1f32` → `1ba5615f` → `079a9cb8` → `efaed4dc` → `801eec3f`.
   The frozen tag (phase 1) is `08239bcfedc3`; the best tag is `ba34625e224f`.

## How it was measured

- **Board:** FireSim on an Alveo U250, `FireSimGemminiRocketConfig` (the stock configuration, with a full-width accumulator
  readout).
  - Bitstream sha256 `a9a190b9fc26d577b1e8af0e3b46a94c8efaf2976f7fca6650236e0fd6d4eca1`; Merlin registry pin `firesim_gemmini_rocket_u250`; queue hw-config
    `alveo_u250_firesim_gemmini_rocket_stock`.
  - Parameter header `gemmini_params.h`, sha256 `3758ae967af3a179497660970201093a7fb624be00173990ce33d3f5c38da924`, generated by the elaboration.
- **Program:** ResNet-50, int8, 71 groups. Merlin's whole-model harness built it with
  `prohibited_roles: [loop_descriptor]`. ELF sha256 `d8d3627effb2421c2f763c1010b62cfc616b94a8f6c54f67b771b3e488ae728f`.
  - This package's kernels run 70 groups.
  - The Rocket core runs 2 groups: the input quantize and the classifier (FC, 3,663,654 cycles).
  - The vendor library runs 0 groups.
- **Window:** `MERLIN_WINDOW group_model`, with one warm-up invocation and one measured invocation.
  - The number is the whole window, `FM full model cycles`.
  - Of that, 38,050,566 cycles fall inside the per-group brackets and
    46,869 fall between them.
- **Control:** the vendor-library reference ran in the same board job (job 1939, a batch of 2).
  - It read 29,805,343 cycles there, against 29,486,974 in its
    own solo run (job 1916).
  - That is a ratio of 1.0108, inside the 0.02 tolerance, so the board was behaving normally.
- **Correctness:** 71/71 groups were verified
  against the functional model (Spike with libgemmini).
  - The board's bytes equal the functional model's bytes.
  - The predicted class is 21, which equals the oracle's 21.
- **Exactness:** each group was held to the target's reviewed contract, `examples/gemmini/phase2/exactness.yaml`.
  - Every form is exact; where an op declares its own bound, that bound applies.
  - 55 groups are exact. 16 are within their op-declared bound (bounded(<=1 LSB) x8, bounded(<=2 LSB) x7, bounded(<=4 LSB) x1).
  - The measurement recorded no contract of its own. Merlin's `exactness.apply_to_verdict` re-applied the
    contract at export and changed no group.
- **No-FSM check:** a whole-ELF scan of the program is clean. None of the
  14 loop-descriptor instructions appears (selectors 8–13, 15–21, 24).
  - Positive control: the same scan finds 6 such words in job 1882's ELF.

- **GSIM certification:** Merlin's `merlin-whole-model-gsim` ran the whole model on the GSIM emulator of the
  elaborated `GemminiGsimSerialClkConfig` RTL, with the same header `3758ae96`.
  - **Emulator:** the dump-capable build `7d6e5e38`. It agrees with the pinned
    `gemmini_gsim_emulator` on all 12
    equivalence captures.
  - **Result:** 71/71 groups correct, graded from an end-of-run memory dump against the oracle.
    The argmax read from the dump, from the core and from the oracle are all 21.
  - **Program:** the GSIM build uses the same package, capsule, weights, header and no-FSM rule as job 1939.
    70/70 package kernel objects are byte-identical to the stock timing build's; the programs differ only in the harness (host_dump writes outputs for a memory dump instead of checking them on the core, which an RTL simulator cannot afford).
    Its ELF `9a11fb49` is also scan-clean.
  - **Cycles:** GSIM read 37,061,012 cycles. These are elaborated-RTL cycles, and Merlin's
    measurement ladder does not accept them as the device's cycle count; FireSim is the cycle authority.

## What this does not claim

- **Not faster than the vendor library or Exo.** This package is 1.26–1.29× the vendor library and 1.70× Exo on
  the stock board. Neither reference is like-for-like:
  - The vendor library uses the hardware loop instructions (FSM).
  - Exo is a different program with its own input, and its ELF holds 6 loop-descriptor words. Whether they
    execute is unknown.
- **The roofline is an estimate.** It is a sum of per-group lower bounds derived from the RTL facts (16×16 mesh,
  16 B/cycle). It was derived while the `gemmini_rtl` pin was drifting.
- **The two boards are different devices.** Never compare a lean number with a stock number.
- **34,661,123 (job 1882) is not a result of this champion.** It is not a no-FSM number: that build routed the FC
  through the vendor library, which put 6 `LOOP_WS`-family words in the ELF. It also ran solo, with no control.
- **Correctness covers one input.** It means one ResNet-50 input, checked group by group, with argmax 21 matching
  the oracle. It is not accuracy over a dataset.
- **Not a sealed result.** See the legacy lineage in `MERLIN_PUBLICATION.md`.
- **The payload gate is a separate record.** `.merlin/certification.yaml` belongs to the publish layer's own,
  optional gate: `oot_runner.certify` rungs bound to the payload bytes. No such rungs were run for this package,
  so that file reads `unverified` in its `package-payload` scope. The champion's certification is the evidence
  profile above.
- **Provenance gaps:**
  - The measurement records carry `hardware_pins: {}`; the pins are cited here by registry key and digest.
  - The harness ran from a Merlin snapshot with uncommitted edits (`792c9a5f` plus 8 dirty files).
  - The stock bitstream was built from a dirty FireSim checkout and has no `built_from`.
- **The ResNet-50 program is not in this repository.** Its harness, weights and oracle belong to Merlin; this
  repository is the compiler.

## Using it

The tool needs Python 3 and `xdsl` 0.68.0, which is not vendored. It was verified with Python 3.12 and 3.13; other `xdsl`
versions are untested.

```sh
git clone -b champions/phase2/801eec3f https://github.com/ucb-bar/gemmini-mlir.git gemmini-mlir-801eec3f
cd gemmini-mlir-801eec3f
sha256sum -c --quiet .merlin/records/SHA256SUMS      # the measured bytes
python3 -m venv .venv && .venv/bin/pip install xdsl==0.68.0
. .venv/bin/activate
./gemmini-opt --verify-diagnostics input.mlir                                   # parse
./gemmini-opt --convert-iface-to-gemmini input.mlir                             # lower to the gemmini dialect
./gemmini-opt --convert-iface-to-gemmini --emit-command-buffer=cb.json input.mlir
./gemmini-opt --convert-iface-to-gemmini --emit-target-artifact input.mlir      # LLVM artifact
```

- **Input:** `input.mlir` is a module in Merlin's interface dialect (`merlin_iface`), the form Merlin's frontend
  produces for each capsule or group.
- **Commands:** `manifest.yaml` declares the exact argv of each command Merlin's experiment ABI uses.
